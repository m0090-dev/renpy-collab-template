# 開始メモ（マスター・汎用）

このリポジトリで作業を始める AI は、まずこのファイル、`docs/PROJECT.md`、
`docs/RULES.md` を読むこと。
作業ブランチに影響する操作の前に、必ず main の最新版を参照する。

## 手順

1. このファイル、`docs/PROJECT.md`、`docs/RULES.md` を読む。
2. ユーザーに役割を選んでもらう（勝手に決めない）。
   選択肢は `PROJECT.md` の役割表から作る。「確認だけ」は常に含める。
3. 選ばれた役割のメモ（`PROJECT.md` の役割表に書かれたファイル）を読む。
   パートナー向けメモが存在するプロジェクトでは、対象の側のチャットはそれも読む。
4. 最新の main から作業ブランチを作る（命名は RULES に従う）。「確認だけ」なら作らない。
5. 「準備できた。役割は○○、ブランチは○○」と短く報告する。

## 大原則

- main は常に「公開できる状態」。直接の作業は作業ブランチでだけ行う。
- ルールと設定の正本は main の `docs/`。古い・合わないと感じたら、その旨を報告に含める。
- プロジェクト固有の事情（使用ツール、公開方法、素材の扱い）は `PROJECT.md` と
  エンジン固有の注意書き（`docs/NOTES-renpy.md` 等）が優先する。

## GitHub 連携の前提（書き込み操作について）

作業ブランチへの push、PR の作成、Issue の作成など、「自分の身元で GitHub に
書き込む」操作は、その操作を行うエージェント（Muse・Claude 等）に次の条件が
そろっている場合にだけ可能。

- そのエージェントに GitHub 連携（アカウント接続）がされている。
- 本人が、このリポジトリに collaborator として招待されている。
- 連携アプリの「対象リポジトリ」に、このリポジトリが追加されている。

条件が1つでも欠けると書き込みはできない（権限エラーになる）。
また、push 等の書き込みのたびに、本人の承認が要る（自動では送られない）。

- public リポジトリの clone / pull（読むだけの操作）は、連携なしでも可能。
- private リポジトリでは、読む操作にも連携・認証が要る。
- 連携できないエージェントは、確認・相談・提案・報告文の作成までを担当し、
  push は連携できる側のエージェントが代行する。
